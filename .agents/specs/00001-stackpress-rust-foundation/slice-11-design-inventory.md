# Slice 11 upstream package inventory

Status: Draft / Not Frozen. Source root is the read-only packages/stackpress in the original Stackpress checkout, version 0.10.8. All **43 non-generated package files** are hashed in [provenance](slice-11-design-provenance.md); all named re-exports/types are enumerated in the [export ledger](slice-11-design-exports.md). Generated cjs/esm output and installed dependencies are not canonical source or additional Rust implementation evidence.

## Disposition vocabulary

**Now / reuse** means compose an existing Rust capability without changing its contract. **Now / bridge** is real aggregate work still to implement after release. **Not ported as JS API** retains the source capability through the accepted Rust/Leptos/compiled-tool representation, without reproducing JS classes, React hooks, Node objects or hundreds of root aliases. **Later** names an explicit follow-up; none is silently called complete. Inventory is not a claim that every TypeScript helper already exists under the same name.

## Command inventory

src/events.ts exports **develop, emit, serve, generate, install, migrate, purge, push, query, populate, uninstall, upgrade**. src/scripts.ts exports the same set **without query**. Namespace names and that difference are intentional. They delegate to stackpress-server/schema/sql rather than define a second implementation.

| Command family | Rust plan / boundary |
| --- | --- |
| develop, serve | Source event request/config/default/error plumbing over explicit app native command binding. Existing HTTP host/build tooling owns actual IO. No watcher/listener at registration, build or finite proof. |
| emit | Reuse CLI parsing, request construction, named capability dispatch and existing output/error handling; preserve raw nested versus top-level handling. No unrestricted remote endpoint added. |
| generate | Explicit owned build-host request/callback over current Registry/normalization/OutputWorkspace; preserve source input/result ordering. Dynamic JS generators become compiled transforms. Runtime aggregate merely registers the explicit command bridge. |
| install, migrate, purge, push, populate, uninstall, upgrade | Explicit operator commands over current schema/SQL plans, Actions, application seed/population functions and accepted maintenance policy. Source invocation order/errors recorded; no automatic execution or disabling of existing operator review/sequence contracts. |
| query | Event-only export in aggregate source; explicit existing Engine/query capability, no invented script alias or public HTTP query route. |

At M0 inspect the actual delegated command modules for input/default/result/error traces before implementing their bridge; the aggregate's re-export file alone proves names, not their internals. Source Node process/watcher/module-import details remain named mechanics limitations, not empty successful results. This design does not reopen completed lower-library contracts or promise remote/live execution.

## Public export completeness

The [ledger](slice-11-design-exports.md) lists every named export with its origin, kind, source line and disposition family, including names only reachable through subpaths and names in source modules not declared as package subpaths. Every ./types family and HTTP/WHATWG/backend wrapper is included. package.json has 30 export keys; root index has no default aggregate export (./plugin is separate). No tests directory exists in this package snapshot despite package test-script patterns. Proving behavior therefore requires source-derived traces plus real Rust constituent/consumer tests, not an invented upstream test count.
