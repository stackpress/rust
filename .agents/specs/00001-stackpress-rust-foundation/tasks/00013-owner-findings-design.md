## F02: failure/interruption before document completion

Keep S7/S8 stop-after-commit semantics: no replacement status, appended JSON, retry, lifecycle reentry or hydration of partial markup. Server-only failure templates cannot cover transport deadline/disconnects; CSS can reveal an arriving marker but cannot distinguish missing completion from loading. Inline executable status scripts would need nonce integration that the current renderer does not offer. The current deferred module's failure branch cannot be relied on to execute after an aborted document.
Choose an **external classic async status asset** in the opening shell, before `#app`, independent of the WASM/deferred bootstrap. Proposed additive renderer method `with_status_script(PublicLocation) -> Result<Self, ViewError>` emits that optional base-validated asset; export its fixed implementation as `stream::STREAM_STATUS_SCRIPT` for host manifest packaging. Existing renderer callers and PageAssets wire shape stay compatible. Opt both ui-stream host entry points into it; extend build/manifest/review bundle handling for `stream-status.js`.
The script only updates the precommitted recovery notice using textContent/attributes. Observe fixed completion/failure markers plus parsing-end/readyState events; failure marker or parsing end without completion gives role=alert and **“This page didn't finish loading. Reload this page.”** An independent six-second watchdog, beyond this example host's four-second stream budget, covers browsers that abort without an observable end event; its honest text is **“This page hasn't finished loading. Reload this page.”** It makes no claim about the transport reason. A later verified completion may clear that unfinished state; a failure marker remains terminal. Remove observer/listeners/timer on completion/pagehide.
No eval/innerHTML, inline handlers, raw user text, resource decoding, WASM start or network retry in the status asset. Its fixed reload anchor is the renderer's checked document URL. Host CSP must explicitly permit this same-origin manifest asset; do not add unsafe-inline or invent a nonce. Nonce-only policies need a separately approved integration, not a silent bypass. The [HTML async-script contract](https://html.spec.whatwg.org/multipage/scripting.html#attr-script-async) permits execution before parsing finishes; [CSP](https://www.w3.org/TR/CSP3/#directive-script-src) remains host-owned.
Retain completion+failure checks in bootstrap.js before replay/admission/hydration; completion hides the notice only after successful startup, and startup errors remain visible. With JS/CSP/asset failure, the static notice must say “Loading or interrupted; reload if this page does not finish”, never promise an automatic update. No-script users retain the safe link; automatic transport classification is not claimed there.
M4 carry-forward from M0 review: prefer definitive “didn't finish” text if the late-case failure marker or non-loading readyState is observable; otherwise retain the honest six-second fallback and explain why it is the visible text. No streaming change is released by M1.
Files/crates: framework-ui `stream.rs`, new status JS asset/source and stream tests; ui-stream bootstrap/build/web/browser proofs; review bundler/smoke. First proof must use real native pipe/duplex bytes through intercepted browser streaming with abrupt ReadableStream/network error, not convert failure to clean EOF. Cover late/pending/deadline, delayed status asset, actual missing terminal chunk, CSP with inline scripts forbidden, navigation cleanup, successful slow completion and zero replay/fetch/hydration on partial pages. Prove native stop/reap separately; do not infer browser handling from collected HTML.
