### Rust mechanics necessities and evidence limits

Typed config, existing method/path grammar, request/value budgets and response-state errors remain inherited host boundaries. Malformed dynamic scopes become a framework runtime Error (500), representing source property/method failure rather than a native JS TypeError object. No new admission policy is inferred.

Existing Nest cannot represent undefined: an absent Session row profileId removes that key after fixed overlay; read/JSON omission matches source, while `has()` differs from source's own undefined-valued property. Existing owned maps/values also do not preserve JS alias mutation or object insertion order; overlay iterates the Rust Nest map order. Empty-key append behavior is pinned in that representation, without claiming every JS property-order-dependent collision is identical.

Method selection reuses the existing host's `MethodPattern::Any` for ALL; it admits valid HTTP extension tokens beyond the upstream router's letter-only regex (`ingest/ingest/src/plugin/ActionRouter.ts:260`). This is an inherited matcher representation difference, not an API-added security rule; no shared router changes were released. Path captures/grammar likewise use existing RouteSpec. Standard/letter-extension parity is proven; punctuation-token equivalence is not claimed.

M1 real SQL/Profile/default-provider integration is still pending coordinator release. M3 will add the source endpoint-gated OAuth/token/consent bindings; M4 adds webhooks; M5 adds complete UI/management. M2 deliberately installs no placeholder page handler.
