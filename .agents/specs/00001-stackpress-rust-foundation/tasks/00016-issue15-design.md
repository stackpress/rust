## G39 values, first paint and persistence compatibility

Remove both System variants, their match arms/defaults, `SYSTEM_THEME_STYLES`, `SystemThemeStyles`, `components/system.css`, System control and live media-query selectors. `Theme`/`ThemePreference` contain Light/Dark only. Saved choice and effective UI state are separate: `Preferences.theme: Option<ThemePreference>`; native defaults use None. `SettingsUpdate.theme` is optional too; `SettingsAction::new(registry,scope)` loses its theme-fallback argument.
Approved `PageContract.theme`/`PageSnapshot.theme: Option<String>` with checked Some("light"|"dark") or None; fixed-setting pages retain explicit Light defaults. Missing/null is unset; hosts emit no `system` token. Retain JSON field names/envelopes, command names, revision 1 and exact light/dark replies; unset uses `theme:null`. No unrelated search/CRUD wire change.
Legacy cookie `system` selects None; a dedicated stored-file compatibility decoder maps only legacy `system` to None before normal validation, preserving locale and `recovered=false`. Null/missing represents absence; malformed/unknown file values keep existing recovery behavior. Never serialize System or rewrite/delete a legacy cookie/file merely to read it. Locale-only saves retain the optional saved choice and never promote the effective OS-selected color into a saved choice.
Only unset SSR uses one tiny checked, same-origin **external classic head asset**, without async/defer, before themed content; optional checked, content-fingerprinted bootstrap metadata belongs with `PageAssets`, not executable seed JSON. It samples `matchMedia` once and freezes Light/Dark on a document-owned attribute. Record byte size and prove cacheable delivery, no change listener/storage access/fetch/persistence callback and no network requests beyond itself. Saved Light/Dark renders directly from SSR with no pending marker or asset dependency. [HTML script ordering](https://html.spec.whatwg.org/multipage/scripting.html#the-script-element) informs the proposal; M0 proves actual paint behavior.
SSR colors use the frozen ancestor attribute through scoped initial selectors, overriding only roots marked pending; generic independent roots stay isolated. Hydrate the unchanged server subtree/seed first, then synchronously adopt the frozen theme and remove its pending marker in one root update before the next paint; never rewrite inert seed JSON or replace nodes. CSR consumes the frozen value before mounting. OS changes after capture, locale saves, failed saves and navigation in that root never resample it.
Native CSR keeps themed content gated until the existing fixed load command finishes; saved Light/Dark wins, otherwise sample once before first mount. A locale acknowledgement with None reuses that frozen color. Preserve existing load/write deadlines, recovery notice and command admission; do not let a speculative OS choice paint before a saved choice loads.
CSP permits the exact same-origin asset (`script-src 'self'`, or a response nonce on the external tag under stricter policy); no inline executable script, eval or blanket unsafe-inline. Ship trusted initial selectors in an admitted stylesheet, including streamed shells. G40: absent/blocked/no-JS bootstrap leaves unset SSR Light, fully readable and usable with no blocking shell; known saved Dark stays Dark. No CSS live `prefers-color-scheme` tracking. Native CSR's existing pre-mount acquisition remains distinct from readable website SSR.
Compatibility fixtures pin `stackpress-locale`, `stackpress-theme`, `stackpress-flash`; mount Path, HttpOnly, SameSite=Lax, HTTPS Secure/explicit HTTP exception; preference Max-Age 31536000, flash 300 and deletion scope. Prefix > canonical cookie > configured default, aliases, unknown/duplicate prefixes and exact encoded query/return bytes remain unchanged. Theme None emits no theme cookie; readback accepts absence/legacy System only for None and never emits Set-Cookie. Explicit saves still confirm exact cookies before publication.
Native fixtures pin `ui-preferences-v1.json`, revision 1, `.ui-preferences-v1.pending`, 1024-byte bound, private-directory/exclusive ownership, no-follow/nonblocking regular-file checks, 0600 create-new staging, sync/rename/directory-sync. Missing is normal; corrupt/truncated/oversized/symlink/FIFO recover without modifying input; late failure remains uncertain persistence. Failed/aborted/unconfirmed operations retain acknowledged values, location, focused input and unsaved drafts; no retry or rollback claim.

## Ordinary plugin entry points

Convention: a package's real composite uses `framework_view::plugin::register`; an independently selectable capability uses `framework_view::{preferences,flash}::register`, each `fn(&mut ServerBuilder)->stackpress_lib::Result<()>`, gated by its host feature. Reserve the base composite for #14 until it has real responsibilities; do not add an empty callback or require a fictional base plugin.
Here preferences registration validates typed app configuration (registry, mount, canonical origin, explicit settings/confirmation paths and session CSRF admission), constructs a settings service and registers only those fixed POST handlers. Flash registration installs its bounded service and explicitly scoped consume/clear hooks; public loader projection and notice issuance remain deliberate. No database, migrations, seeds, filesystem, network or generic event exposure at startup. Native files remain direct opt-in host adapters, not an implicit Tauri plugin.
Use existing config/startup queues, `app.plugin("view-preferences", framework_view::preferences::register)?` and `PluginSpec` only for real prerequisites. Application composites call contribution functions, never nested `app.plugin` after selection seals. Missing required configuration/policy, duplicate services/routes and dependency/order failures reject build before publishing a Server; a sessionless preferences host declares that policy explicitly. Selecting libraries/features alone installs nothing; omission leaves cookies/files untouched and fixed-settings pages usable.
`HostAccess::run` remains immediately before every protected operation, with fresh authoritative context; None denies. Presentation selection, `AllowedActions` forgery, missing flash/preferences and client state cannot bypass this gate. Keep identity/resource/Origin/CSRF decisions app-owned; no auth framework is added.
