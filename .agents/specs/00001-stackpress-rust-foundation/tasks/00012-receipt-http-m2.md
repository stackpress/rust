## Deployment and TLS

- `NetworkOptions::http` / feature-gated `https` choose deliberate transport and trusted startup policy. `HttpServer::from_options` validates the same configuration/TLS path without binding, for supplied IO. `HttpServer::bind` prepares first, then creates one TCP source and returns `BoundHttpServer`; it starts no serving task.
- `BoundHttpServer::serve_until(stop)` delegates to `Arc<HttpServer>::serve_acceptor_until(acceptor, stop)`. The generic seam owns the exact same stop-future, admission, drain/abort/reap path. Source/listener/backlog is dropped before active connections drain. Fatal accept errors are retained in `DrainReport::failure` after cleanup rather than discarding the final report in an outer error.
- `serve_io` honors prepared HTTPS. A trusted generic Acceptor explicitly chooses `AcceptedIo::plain` or `tls`; remote headers never choose transport. Legacy `HttpServer::new(HttpOptions)` retains its existing compatibility behavior; production callers select deployment authority policy through `from_options`/`bind`.
- `TlsFiles::pem` or explicit DER loads a regular chain file <=64KiB and key <=16KiB, with no symlink components. PEM requires exactly one private key. Rustls validates chain encoding/key compatibility before bind; invalid/missing/oversized/mismatched material never falls back to HTTP. Identity and CA verification remains the client responsibility, with M0 valid/name-mismatch proofs retained.
- File contents are consumed at preparation; later handshakes do not reopen them. Ring, TLS 1.2/1.3 and HTTP/1.1 ALPN remain explicit. No issuance, discovery, reload, mTLS or HTTP/2 claim. Startup reads are synchronous/bounded and require operator-owned unchanged files; portable metadata/open is not atomic against hostile replacement.
- The compile-checked `examples/deployment.rs` accepts `--port`, serves `/health`, `/assets/hello.txt`, `/stream`, registers caller-owned Ctrl-C/Unix SIGTERM input before readiness, awaits full drain before dropping application services, and retains fatal accept/stop causes without automatically logging their text.

## Authority and proxy trust

- Deployment requests require exactly one Host. Host and absolute-target authority must match each other and a literal configured allowlist. Public-origin authority is included; additional entries are explicit, bounded, without wildcard matching. DNS case/default ports/equivalent IPv6 spellings canonicalize; malformed ports, userinfo, escapes and mismatches reject empty 400 before callbacks.
- Default and untrusted peers cannot change trusted metadata with forwarding fields. `ProxyPolicy` selects one header family, 1–32 exact hops, and <=128 concrete peer CIDRs. Immediate peer and every declared intermediary must match; IPv4 and IPv6, including mapped addresses, never implicitly acquire each other's trust.
- Forwarded: one line, each hop has for/proto/host once; quoted bracketed IPv6 with optional port is supported. XForwarded: one For/Proto/Host line each with the exact configured count. Mixed families, duplicate lines/parameters, partial/obfuscated/unknown identities, unsupported extensions/escapes, extra/missing hops, inconsistent origins and untrusted intermediary addresses reject before routing.
- Protocols are canonical HTTP(S); forwarded host/port must be allowlisted and absolute targets must agree. Canonical checked external origin supplies informational request URL/context; native path/query remain authoritative. `HttpRequestContext::scheme` still describes actual transport. `forwarded_client: Option<IpAddr>` is informational, never authorization.
- This is an intentionally strict forwarding subset; the deployment proxy must emit that contract. The M1 accepted authoritative-Hyper CL/TE policy remains unchanged, including unconditional close after a TE request. No raw framing parser/preflight/fork/direct httparse dependency was introduced.

## Immutable asset routes

- `AssetBundle::load(root, manifest, AssetLimits)` bounds serialized JSON before parse; rejects unknown/duplicate fields, invalid count/descriptor budgets, duplicate routes, invalid SHA-256/size/MIME/cache. It preloads only verified regular files and retains immutable `Arc<[u8]>` bytes.
- Defaults: manifest 64KiB, 1024 entries, file 64MiB, retained bundle 128MiB. All descriptors/aggregate budgets are checked before asset opens. Each file read is further capped by its declared size. SHA-256 and actual size must match before retention.
- Route/file components are literal ASCII alphanumeric plus `-_.`, without empty/dot/parent segments, patterns, percent/Unicode names, backslash, query or fragment; file names are relative to the operator-owned root. Symlink components/FIFOs/directories/devices are rejected before open. Concurrent hostile mutation is outside the accepted immutable-tree contract.
- Call `bundle.register(&mut ServerBuilder)` **before** build/bind. These are ordinary exact GET/HEAD routes with normal request/error/response ordering, request guards and independent Set-Cookie handling. The built server cannot receive new registrations during bind; startup asset verification therefore precedes application build, rather than introducing another request dispatcher inside the TCP adapter.
- Known verified Content-Length, hash ETag, nosniff and explicit MIME; conditional weak/strong If-None-Match or `*` selects 304. Revalidate uses public/max-age=0/must-revalidate. Immutable uses public/max-age=31536000/immutable and requires the full content hash in the basename. Unknown routes remain 404; no directory/SPA fallback, ranges or compression.
- Additive `HttpResponseExt::immutable_bytes(mime, Arc<[u8]>, StreamLimits)` keeps one-shot response publication, explicit finite byte/chunk/time policy and known length, yielding at most min(configured chunk,64KiB) per demand. It never copies a whole representation at attachment; HEAD/bodyless output takes/drops without polling. Existing buffered HTTP still rejects native descriptors. No HandleReport method or lifecycle-publicity change was needed.

## Bounded observation ownership

- `ExchangeObserver` receives fixed-size `ExchangeObservation`: checked host-local connection/exchange IDs, status, duration, handed-off bytes, delivery, error kind and completed host-report presence. No URI/path, request IDs, headers/cookies/auth, client IP, body, SQL/binds or native source text is present.
- Optional callbacks have no library queue/detached sender. Connection history remains bounded by existing request/admission budgets; final snapshots emit at connection ownership end, outside all registry/body/admission locks and after active future/IO/permits drop. The callback must be synchronous/nonblocking; its storage/forwarding is application-owned.
- A private observed-future owner drops its pinned inner future before callbacks on completion/cancellation. Callback authority is consumed before entering user code, so callback panic is not retried. Task poll panic yields redacted final failure metadata outside unwind, then resumes the **original** panic payload for normal JoinSet handling. Drop already unwinding skips callbacks to avoid a second panic. Completed still requires producer handoff plus native flush, never remote ACK.
- Native policy errors retain their original typed causes; DER's static pki format reason has a private Error wrapper. No wrapper interpolates a native cause's Display. Debug reporting remains redacted.
