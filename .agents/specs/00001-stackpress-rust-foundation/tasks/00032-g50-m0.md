## Implemented boundary

| Owner / public path | Contract and evidence |
| --- | --- |
| `stackpress_framework_schema::source::{SourceSchema, SourceField, Id}` | Native-only, no optional feature or new dependency. Associated owned Value/Record preserve room for native Dates and ordered extension fields, without Serde bounds or public DTO conversion. Immutable seed/offset construction; describe/defaults/filter/populate/assert/serialize/unserialize signatures. `SourceField` reads/writes the schema's actual record with a declared associated field type. |
| `stackpress_framework_sql::source::{SourceModel, SourceStore, SourceActions}` | Model associates its exact schema/store/actions/role. Pure stores prepare query/DDL/codecs. Actions own Arc<Engine>; `_in` methods borrow the exact exclusive DataSession and input/query. All futures require Send. CRUD pooled methods delegate to those same borrowed implementations. Batch/setup signatures add no guard, implicit transaction or policy. |
| `source::{SessionModels, ApiModels}` in framework-sql | Session family supplies Profile/Auth. `ApiModels: SessionModels` adds Application/Session, inheriting exactly one Profile type. Role markers prevent accidental cross-role bindings; string-ID field witnesses reject an incompatible app declaration. |
| `stackpress_framework_schema::codegen::EmissionSemantics` | Explicit Typed/Source selection; Typed is default. Schema `emit_contracts_with_semantics` and SQL `emit_stores_with_semantics` preserve existing Typed bytes. Source returns typed Unsupported before adding files at this stage. Full source emission is not implemented or silently substituted. |

The additive source modules are absent on wasm32. Existing strict normalization, handlers, OperationPolicy, contracts and emitter entry points remain unchanged. No source model is selected by existing session/API/aggregate runtime code. G42/G43 behavior is unchanged.

| Independent compiled families | `/private/tmp/g50-m0/probes.py`: two disposable standalone apps, `default` and `app`, copy the existing aggregate full consumer graph/lock, rebase only path locations, and compile/run plus Clippy -D warnings. Both construct all four roles; Profile creates/reads real SQLite rows retaining Date and nickname. `ApiModels<Profile = generated::Profile>` compiles. | Owned/borrowed actions | `tests/main/source_models/ownership.rs`: pooled CRUD/batch/setup signatures run against a real SqliteDatabase; borrowed create/update/read use one caller-owned transaction. Rollback removes the borrowed write; a returned owned Date/record outlives the DataSession and rolled-back transaction. Mutable update input is retained across the method borrow. |
| Send / no model lock across await | Every trait future requires Send; positive futures are checked as Send. Immutable probe state contains no model/config lock. A real provider is suspended before submission while the same actions/schema are re-entered. The contract cannot statically prohibit every downstream Send lock guard; this proves the provided mechanics implementation, not arbitrary future implementations. |
| Cancellation / fail-fast | Suspended borrowed find is cancelled, releasing its Rust borrow; the caller reuses the exact executor and rolls back. The entire ownership scenario runs in a child under the existing external watchdog with a 20 s deadline; a ready-then-park negative control is forcibly killed/reaped after 1 s. Cancellation is not claimed as remote rollback evidence. |
| Session-only external links | `emission.rs::session_only_external_reverse_links_remain_declarations` composes the actual shipped session source with an app addition. Only Profile/Auth exist; Application/Session references remain declared. No hidden API tables/stubs are synthesized. Source normalization/emission of those external references is M1 work, not proved by this composition-only check. |
| Explicit source refusal / typed parity | `compiled_emission_selection_preserves_typed_and_refuses_partial_source` byte-compares legacy and explicit Typed contracts/metadata/stores. Both Source entry points retain SchemaErrorKind::Unsupported beneath their error cause and add no partial files. |

The tiny mechanics helper uses Vec-backed ordered records, its own Date variant and INTEGER Date storage. It does **not** implement full source preparation, hashes/encryption, source query/return/batch behavior, FK setup or the shipped full four-model graph. No source-parity claim is made for those probe implementations. They supply real ownership/SQL substitution boundaries until the later source runtime/generator work.

## Assessment before M1

The ownership and type-association mechanics are viable for M1–M3, **not a frozen complete plugin contract**. Before M1 is integrated:

- Add generated typed witnesses for the remaining required Profile/Auth/Application/Session core fields. M0 checks string IDs only. Do not infer compatibility from erased JSON or repair overriding declarations.
- Choose the extracted common native Value/Record/error representation and make cross-model record compatibility explicit in family bounds (or equivalent typed transfer operations). Current associated types are per model; the probes share them, but the traits do not yet require shared Value/Record types across roles. This must be settled before generic auth/API collaborators use them.
- Release the native source runtime/provider feature/dependency grants needed to extract reusable Date/coercion/codec mechanisms. M0 deliberately avoids a manifest change; it does not extract stackpress-lib DataMap/SourceValue.
- Add source-aware normalization, preserving all shipped constructs and declared external references, then implement real source emitters. Production Source selection currently refuses. Existing Typed semantics and emitted bytes must remain stable.
- Keep generated named-event registrars as ordinary optional server functions, reconciled with the later family/catalog binding work. No registrar/CompiledClient API has been added in M0; default family generation and runtime plugin migration remain separately released stages.

These are Rust contract/generator mechanics already within the accepted staged objective, not new security policy or owner product choices. Stock signup inputs and the session-only external-link answer remain unchanged. No new owner decision is requested at this stop.
