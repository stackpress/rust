## Implementation notes

- [Native SQL registration](../../../../crates/framework/framework-sql/src/plugin.rs): `plugin::register(&mut ServerBuilder) -> stackpress_lib::Result<()>`, gated by `server` and native target. Config verifies the app's existing Engine and Policy and publishes opaque Service. Listen validates 1–128 compiled Contributions, then invokes them with one operations::Registration. There are no SQL config sections, inferred routes, Engine factories, database setup, or network listeners.
- [Generated host template](../../../../crates/framework/framework-admin/src/codegen/templates/pages_host_registration.rs.tpl) and [emitter](../../../../crates/framework/framework-admin/src/codegen/pages.rs): nonempty effective page selections get `pages_host::register` and checked `Mount::new(&str)`. Config requires Mount and the SQL plugin Service, claims the generated singleton and publishes Contributions. Route installs the same selected mappings. Engine/Policy alone cannot satisfy admin integration. Empty/removed selections get no empty registrar. Existing direct operations/routes helpers remain usable. Path-only maintenance in [task 00025](00025-tiny-template-generation.md): the byte-identical registrar asset was renamed from `pages_host.rs.in`; the M2 behavior/evidence above is unchanged.
- [Admin host](../../../../examples/generated-admin/web/src/host.rs) supplies policy, Engine, host config, origin and Mount explicitly from the same validated input, then selects SQL before generated pages with PluginSpec. Existing page/API/transfer handlers and the dispatcher are unchanged.
- Build-tool helpers: [schema::codegen::register](../../../../crates/framework/framework-schema/src/codegen/mod.rs), [sql::codegen::register](../../../../crates/framework/framework-sql/src/codegen.rs), and [admin::codegen::register/register_pages](../../../../crates/framework/framework-admin/src/codegen/mod.rs). They register real ownership/dependency metadata with the existing Registry. Role-only admin requires schema; page generation requires schema and SQL. Both application tools now use these helpers. Normalization, diagnostics, policy and selection remain application-owned.
- [Admin tool](../../../../examples/generated-admin/tool/src/lib.rs) checks the completed plan actually contains SQL-owned `stores/operations.rs` before publication. A real stores-only plan is refused. Templates changed first; official generation updated only the two page-host files and their managed manifests. Both roots pass second generation and `--check` with zero differences; the workspace generator also reports zero differences.
- Generic shared admin and reusable `stackpress-leptos` remain plugin-free. Runtime/native/browser normal graphs are unchanged. Codegen stays out of final application/browser graphs; tools depend on no generated consumer.

G42 route semantics are preserved, with no Server edits. Multiple handlers may process the same route/event in priority/FIFO order and abort cooperatively. Developers own route inventories; each protected handler enforces its own policy. Plugins retain checks within their own declared inventories.
