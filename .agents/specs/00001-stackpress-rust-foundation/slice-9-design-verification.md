## Rust implementation risks: prevention and proving tests

These obligations concern a correct Rust port, not extra security policy.

| ID / risk | Prevention | Proving test |
| --- | --- | --- |
| I01 Deadlock/reentrancy | No held registry/cache/store mutex across await; explicit ownership of task state | Barrier-controlled concurrent/nested calls, cache load, repository/transport suspension and cancellation in external child; watchdog kills/reaps a deliberately stuck child and each real case. |
| I02 Lost/detached work | Supervise source fire-and-forget hooks with owned requests/payloads and bounded shutdown; do not borrow mutable parent across spawn | Child entry acknowledgement, parent completes without await, callback error/panic/cancellation and shutdown reap; no task skipped because a Rust future was dropped unpolled. |
| I03 Caller state cross-talk | Generic native Request slot only after coordinator release, no JSON deserializer/global root state | Same-request emit sees it; new roots/fresh resolve do not; explicit child transfer, simultaneous users, reload/current-token replacement, SQL policy synchronous read and nonserialization. |
| I04 Backend default drift | Explicit source-compatible JWT/TOTP/MIME/regex/date/codec adapter settings | Cross-language golden fixtures and library boundary tests, including optional exp, short seed, exp==now, no typ, arbitrary claims, JS regex/coercion and source-permitted TOTP seeds. |
| I05 Unintended native leakage | Separate shared DTO/components from native config/services/transport handles | Browser normal-edge tree and JS/WASM sentinel checks; expected source DTO token/QR data allowed, actual configured seed/SMTP/database handles not accidentally serialized or baked in. |
| I06 Unsafe framing/partial Rust mutation | Reuse current lib cookie/header/response contracts and safe IO APIs | Existing framing corpus, repeated Set-Cookie, committed-response behaviour and atomic low-level validation failure; do not change source higher-level policy to hide an adapter mismatch. |
| I07 Storage/provider fidelity | Reuse explicit Engine/transactions only where source does; complete adapters and no invented protocol guarantee | SQLite executions, filter/codec/uniqueness/partial effects, all transport variant fakes/constructors; opt-in live provider/backend evidence separately labelled. |
| I08 Mechanical capability gap | Stop at M0 fit gate instead of silently narrowing source features | Golden vectors for unavailable JS/crypto/date/transport semantics; coordinator releases provider/shared changes as needed. No hand-written cryptographic primitive or claim that approval of Argon2 changed the source format. |

## Fast-failing verification architecture

Use one integration-test binary per new crate with modules. Deadlock-class scenarios run as exact child processes controlled by an external parent, not only Tokio timeout on the possibly blocked runtime. Deterministic barriers/acknowledgements control order; 2-second progress receives identify a missing step. Absolute 15-second per-case deadline, TERM then at most 2 seconds before KILL, reap process group and assert descendants/resources gone. Prove supervisor failure with an intentional blocked child before trusting it; no unbounded join/sleep-order tests.

Nextest narrow edit loops, direct dependents when interfaces change, one warm target per lane and sccache. Gate: fmt, workspace nextest/all-targets/locked/no-fail-fast, separate doctests, Clippy -D warnings, warning-clean Rustdoc, valid explicit native/default/hydrate/CSR/SSR/transport features, external direct/registrar consumers and generated freshness checks. Never blanket all-features incompatible render modes or use stale targets.

Development executable line coverage >=70% per changed crate with tool/target/features/numerator/denominator/exclusions; every parity/branch obligation above remains regardless of percent. Publication later requires >=90% and release permission. Native SQLite is mandatory integration; PostgreSQL/MySQL, live SMTP/SES/sendmail and installed platform checks need explicit target/provider evidence. No repository Cargo or provider checks run in this design revision.

After milestones: test-verified complexity, responsibility/abstraction, consistency/Rustdoc/comments and safety/soundness rounds; no ceremonial edits, repeat only for material findings. Receipt maps all inventories/R/I/UI identifiers to evidence, feature graphs, coverage, failures, benchmark IDs/counts and separate command/Cargo-stage timings. Coordinator re-verifies and owner accepts UI. G43 parity is not a reason to skip Rust correctness tests, nor a reason to add rejected policies.
