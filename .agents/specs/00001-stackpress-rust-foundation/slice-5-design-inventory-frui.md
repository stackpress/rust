# Slice 5 Frui export, type and behavior inventory

Companion to [decisions](slice-5-design-decisions.md) and [view inventory provenance](slice-5-design-inventory-view.md). Source root `../frui/src`, package 0.2.9, assessed read-only 2026-10-25. Rows enumerate declared exported symbols and the default component/factory name. Index re-exports, compound/static subcomponent aliases and package aliases (`base`/`component`, form/view/tool wildcard paths and top-level component shortcuts) inherit the same row. No exported type or helper becomes a literal TS compatibility promise.

## Interpretation and behavior scope

Every source behavior and assertion in a module's corresponding test file follows its row, with explicit exceptions below. “Now equivalent” means the useful semantic subset named, implemented with Leptos/native HTML contracts; React hook/context/FC/JS-prop types and source CSS class snapshots are **not ported as APIs**. “Later” includes all declared props/config/state/helper functions associated with that component, for the named task and reason. Internal style/child helpers are listed too so no source mechanism is silently mistaken for a required public port.

Now equivalents: Button native button/link semantics and disabled/type/attributes; Input controlled text/value/input; FieldControl label/help/error association; Alert safe status/error text; Loader status/busy state; Link safe href/label; List escaped values and empty state; Notifier scoped immediate notify/dismiss state. Reproduce selected behavioral assertions, not arbitrary raw attributes or unsafe href schemes. SSR/browser/CSR equality and keyboard behavior are required.

S5-F1 owns disclosure/navigation/overlay/table/simple form and presentation controls with behavior/accessibility contracts. S5-F2 owns rich editors, media, formatting/locale datasets and specialized input parsing. S5-F4 owns cookie-backed flash/theme/account integration. These are proposed follow-up tasks requiring approval, not functionality hidden in this slice's completion claim.

## Barrel aliases and aggregate exports

- `NotifierCookieOptions` aliases CookieOptions and is S5-F4. `ToastOptions` and its barrel alias `NotifierToastOptions` are react-toastify-specific types, not ported literally; scoped notification configuration now, advanced toast behavior S5-F1/S5-F4.
- `Form` and `View` are namespace aggregates of the module rows, with no independent behavior. `Fieldset` is the default `make` factory with `useFieldset`/`use` aliases: later S5-F1, with explicit Leptos child/value ownership instead of a React factory ABI.
- `BorderStylesTool` is exported from the BorderRadiusTool source in the current root barrel, despite its name. Not ported as a compatibility typo; neither JS styling class belongs in the Rust API.

## Explicit source-behavior differences and proving requirements

- Button/link href handling must reject executable schemes and retain correct button type/disabled semantics; do not claim a source className snapshot proves keyboard accessibility.
- Notification defaults in upstream include 5-second close, bottom-center dark theme and flash cookie path `/`. Immediate scoped notifications are now; automatic global timers/default mutation and flash-cookie consumption are S5-F4. Timers are disposed with the UI root; test duplicate/close/unmount paths.
- Overlay focus trapping, escape/click-away, restored focus and event-listener cleanup are required before any Dialog/Dropdown/Tooltip parity claim. They are S5-F1, not demonstrated by the search form.
- NumberInput cursor mapping, locale/decimal normalization, negative-zero/bounds/hidden-value behavior and Date/Time/phone/file/editor integrations remain S5-F2. A native `<input>` does not satisfy those behaviors.
- Raw HTML passthrough and Formula's invalid→zero behavior are intentionally not ported. Plain text escaping is now; rich content needs an approved sanitizer/grammar and failure policy.
- Conditional/iteration/scoped-context behavior is supplied now by Leptos For/Show/match/context, including empty collections and stable keys; React child-type scanning, sibling chaining and JS callable render props are not reproduced.
- Frui `frui.css` and generated UnoCSS preset are not a required styling dependency. Use explicit small CSS for current components and preserve semantic customization; no copied theme palette or brand claim.
- Barrel exports (`src/index.ts`, base/form/view/tool indexes) introduce aliases, not extra behavior. All `*Props`, `*Config`, `*State(s)`, context, slot and helper symbols in the rows are mapped even when only a component name is re-exported in a top-level package entry.

All source test cases inherit the row's disposition, including cases beyond the shown examples; they are not silently dropped from the backlog. Before a later family is accepted, its implementer re-reads the full source/tests and expands that row into Rust behavioral tests with the target-specific corrections above. No upstream test suite was run or changed here.
