## Module, exports, types and test disposition

All React prop types, hooks and child inspection mechanisms are redesigned as typed Rust props/controllers/slots. Retaining their enumeration is a breadth audit, not a TypeScript ABI promise. Tests that assert only React mechanics or exact source CSS classes are not ported; tests for observable state, options, selection, events, values and lifecycle become native/browser contracts in the stated milestone.

## Semantic exceptions and breadth boundaries

- Explicit controlled state replaces the source's controlled/uncontrolled/default-prop combinations. Native input events, labels, form submission, disabled behavior and original observable option semantics still need tests. Source React hook identity is not a Rust compatibility target.
- Overlay positioning uses bounded measurements and disposed listeners; native dialog is preferred where tested. The source's portal/class snapshots do not prove trapping, Escape, background inertness, return focus or nested/unmounted behavior. No overlay ships from SSR markup tests alone.
- Native table semantics include explicit spans, head/body/foot, grouping, empty state, stripes and optional sticky behavior. Pager/sort/filter are controllers, not data operations; no implicit global URL mutation, virtual rows, spreadsheet selection or editable ARIA grid.
- Specialized decimal/date/phone inputs retain their complete selected helper state rules through pure Rust tests plus real caret/IME interaction. Display formatting does not prove input parity. Unsupported source date/format coercions and ambient timezones are deliberate exclusions.
- Every URL-bearing component has a context-specific policy. Existing safe_href remains unchanged; mail/tel use checked typed values, image loading has explicit source/alt/budget policy, and rich HTML has a stricter URL/resource allowlist. Never broaden generic links merely to accommodate a formatter.
- File selection and preview do not imply a server upload service, arbitrary native path disclosure, type-based trust or malware scanning. Persistent transfer is a named later task. Object URLs are revoked on removal/unmount.
- Source collection add/edit/remove/default/serialization and empty/false/zero cases become tests; array position is never the key. Duplicate or missing record identities are rejected before keyed rendering, preserving Slice 5's fix.
- Existing phrase/notification/layout primitives and all accepted Slice 5 regressions stay intact. A global mutable defaults singleton and the `BorderStylesTool` barrel typo are intentionally not ported. `Form`/`View` namespace aggregates and all package wildcard/top-level aliases inherit their module rows.
- `Fieldset`'s make/use aliases become typed collection state rather than a callable React factory. `NotifierCookieOptions` maps to native cookie policy; react-toastify `ToastOptions`/`NotifierToastOptions` types are not ported. Timers/flash semantics have scoped ownership and M1 disposal/consumption tests.
- Media and rich-editor integrations owns Carousel/Film/image-gallery behaviors, CodeMirror/Tiptap/Mask integration, chart/media adapters and syntax highlighting. File and media transfer owns upload/download/storage workflows. A future Design-system tokens task owns the broader Box/UnoCSS/palette API. These are explicit deferrals; Slice 8 does not claim the whole Frui runtime is ported.

## Required component behavior matrix

For each selected family record native state/limit/error tests, SSR structure, real hydrated input/keyboard/focus, packaged CSR where used, unmount/disposal and 375/1280 px plus 200% zoom. Automated accessibility checks cover names/roles/relationships; manual screen-reader/keyboard review checks behavior that those scans miss. Pure style/type-helper exclusions do not erase component usability requirements.
