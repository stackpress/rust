## Selection and dependency boundaries

- `crates/lib` supplies transport-neutral values, request/response/error, event matching, stable queues and the bounded text-template engine. Keep it independent of native hosts, UI, database drivers and account services.
- `crates/server/server` owns typed configuration, startup, compiled plugin registration and the top-level lifecycle. Its `http` feature adds buffered conversion; `http-stream` adds explicit one-shot streaming. `crates/server/http` owns the separate Hyper HTTP/1 IO host and opt-in Rustls TLS.
- `crates/idea/{idea-parser,idea-transformer,idea}` separate parser/AST, native transform/output ownership and convenience orchestration. They are independently usable; app-owned generators compile before the application they generate.
- `crates/sql/sql` has runtime-independent builders, three dialect renderers and execution contracts. The three adapter crates isolate SQLx/native driver dependencies. `framework-sql` integrates schema, generated stores/actions/events, setup and migration tools; it is a separate layer.
- `crates/leptos` supplies independent Leptos components and rendering, with no Stackpress application-host dependency. `framework-view` owns public page snapshots, presentation preferences/flash and optional host/render adapters. `framework-language` supplies pure locale validation and aliases. The removed `framework-ui` and `framework-preferences` packages have no compatibility shim (G40/G41).
- Schema, SQL and admin codegen run in one app-owned registry/output root. Session/API consume app-generated model families; there is no `framework-models` crate or stock model family (G59). See [runtime](runtime-and-portability.md) for composition and `register_with`.
- Root `stackpress` is a facade, distinct from `stackpress-framework`. Libraries depend on their underlying contracts rather than through the facade; keep dependencies acyclic. `stackpress-cli` is a separately usable library without a stock binary or facade re-export.

Facade base features select the matching optional library. `server-http` selects buffered conversion only; `server-http-host` exposes `server_http_host`, and `server-http-host-tls` adds TLS. `sql-{sqlite,postgres,mysql}` also enable `sql`. Renderer forwarders select separate SSR, hydrate and CSR artifacts; do not combine incompatible renderers with `--all-features`. The complete forwarding lists are in the [root manifest](../../Cargo.toml).
