# Generate and check a temporary application

A codegen tool needs a complete schema before it writes application source. The wrapper
performs that sequence in one synchronous call. This walkthrough creates a temporary native
project, generates a model-name index, and verifies the result with Check mode.

## Prepare a consumer

Create a binary package outside this repository with Rust 1.96 and these dependencies. Replace
the checkout path with your own absolute path.

```toml
[dependencies]
stackpress-idea = { path = "/path/to/rust/crates/idea/idea" }
tempfile = "3"
```

The wrapper's `parser` and `transformer` re-exports supply the other types. `tempfile` keeps
the walkthrough independent of any checked-in application output.

## Run the full pipeline

Put this program in `src/main.rs`. `aggregate` is the app-owned root-file renderer; it sees
the same finalized SchemaConfig view as transform callbacks. An empty registry is sufficient
for this first aggregate-only result.

```rust
use stackpress_idea::{GenerateRequest, GenerationMode, generate, parser, transformer};
use transformer::{GeneratedFile, OutputWorkspace, ProjectLoader, Registry};

fn aggregate(schema: &parser::SchemaConfig) -> transformer::Result<Vec<GeneratedFile>> {
    // Produce a complete app-owned root file from finalized model names.
    let names = schema.model.keys().cloned().collect::<Vec<_>>().join("\n");
    Ok(vec![GeneratedFile::new("models.txt", format!("{names}\n"))])
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let parent = std::env::temp_dir().canonicalize()?;
    let temp = tempfile::tempdir_in(parent)?;
    std::fs::write(temp.path().join("schema.idea"), "use \"./models\"")?;
    std::fs::write(
        temp.path().join("models.idea"),
        "model Profile { id String name String }",
    )?;
    let loader = ProjectLoader::new(temp.path())?;
    let root = temp.path().join("generated");
    let workspace = OutputWorkspace::new(&root)?;
    let registry = Registry::new();

    // Install reports the differences found before writing, not post-install freshness.
    let install = GenerateRequest::new("schema.idea", aggregate, GenerationMode::Install);
    let changed = generate(install, &loader, &registry, &workspace)?;
    assert!(!changed.is_current());
    assert_eq!(
        std::fs::read_to_string(root.join("models.txt"))?,
        "Profile\n"
    );

    // Recompose and replan the same inputs without changing generated bytes or the marker.
    let check = GenerateRequest::new("schema.idea", aggregate, GenerationMode::Check);
    assert!(generate(check, &loader, &registry, &workspace)?.is_current());
    println!("Profile generated; check is current");
    Ok(())
}
```

`ProjectLoader` resolves `models` relative to `schema.idea`. `generate` consumes imports,
resolves surviving real references, renders aggregates, and runs registry planning before
workspace IO. The output root is a sibling of these temporary inputs and has one exclusive owner.

Run `cargo run` in the consumer. It prints `Profile generated; check is current`; failure of
either assertion stops the program. Checking briefly creates a cooperative lock, but leaves
generated file bytes and the ownership manifest unchanged.

## What just happened

The request chose exactly one output mode and supplied bounded defaults for parser inputs,
composition limits, contracts, and auxiliary inputs. The registry had no selected functions
and the root schema had no plugin blocks, so the app aggregate owned the entire plan.

Both calls used the same composition/finalization/planning path. The first installed a marked
tree; the second compared against it. A callback, reference, or preflight error would have
stopped before managed output installation.
