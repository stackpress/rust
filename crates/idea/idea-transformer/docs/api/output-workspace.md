# OutputWorkspace API

OutputWorkspace manages a dedicated native generated root with cooperative ownership,
formatting, drift checks, staged installation, and explicit recovery. It has private fields.
Source: [output.rs](../../src/output.rs).

```rust
use stackpress_idea_transformer::{GeneratedFile, OutputWorkspace, Registry};
let parent = std::env::temp_dir().canonicalize()?;
let temp = tempfile::tempdir_in(parent)?;
let root = temp.path().join("generated");
let workspace = OutputWorkspace::new(&root)?;
let registry = Registry::new();
let plan = registry.plan(
    &Default::default(),
    vec![GeneratedFile::new("index.txt", "Profile\n")],
)?;
```

Each following snippet uses that setup independently and requires `tempfile`. Contents:
[1. Construction](#1-outputworkspacenew) · [2. Check](#2-check) ·
[3. Install](#3-install) · [4. Receipt](#4-install_report) · [5. Recovery](#5-recover)

## 1. OutputWorkspace::new

`OutputWorkspace::new(root: impl AsRef<Path>) -> Result<Self>`

Bind the destination and fixed same-parent recovery/lock siblings.

```rust
let workspace = OutputWorkspace::new(temp.path().join("another-generated"))?;
assert!(!workspace.check(&plan)?.is_current());
```

| Parameter | Type | Meaning |
| --- | --- | --- |
| `root` | `impl AsRef<Path>` | Named dedicated directory with explicit existing parent. |

**Returns** An anchored workspace or invalid-name, missing-parent, symlink, traversal, or IO
errors. Relative roots such as `./generated` work; bare `generated` lacks an explicit parent.
The parent is canonicalized after rejecting symlink components; later cwd changes cannot
redirect it. Construction does not create the root or establish that its contents are owned.

## 2. check

`check(&self, plan: &OutputPlan) -> Result<CheckReport>`

Compare fresh formatted output with installed ownership and bytes.

```rust
let report = workspace.check(&plan)?;
assert!(!report.is_current());
assert!(!root.exists());
assert!(report.differences.contains(&"index.txt".into()));
```

| Parameter | Type | Meaning |
| --- | --- | --- |
| `plan` | `&OutputPlan` | Completed in-memory claims. |

**Returns** Sorted differing paths, including a missing marker. A valid stale tree is an `Ok`
report; manual edits, missing owned files, unknown/manual directories/files, invalid ownership,
formatting, existing lock, retained recovery state, or IO failures return errors.

Check formats `.rs` through `rustfmt` before locking. It briefly creates/removes the sibling lock
but changes no generated bytes or manifest. Non-Rust files retain exact supplied bytes. Both
an absent root and an empty unmarked root are stale, even for an empty plan.

## 3. install

`install(&self, plan: OutputPlan) -> Result<CheckReport>`

Install complete output and remove previously owned paths absent from the plan.

```rust
let before = workspace.install(plan)?;
assert!(!before.is_current());
let again = registry.plan(
    &Default::default(),
    vec![GeneratedFile::new("index.txt", "Profile\n")],
)?;
assert!(workspace.check(&again)?.is_current());
```

| Parameter | Type | Meaning |
| --- | --- | --- |
| `plan` | `OutputPlan` | Completed plan, consumed by installation. |

**Returns** The differences observed before installation. A first successful install therefore
usually returns `is_current() == false`; repeat installation returns an empty report and
preserves bytes without unnecessary renames. Use a subsequent check for post-install freshness.

The first root must be absent or empty. Existing output must be recognized and exactly owned
by `.stackpress-generated.json` version 1. Owner/content comparisons follow digest validation;
no manual file or edit is overwritten. Formatting and ownership failures precede destination
mutation. After intent publication, installation IO errors retain stage/backup/journal and
name the phase; subsequent normal runs refuse until recovery. A complete stage before intent
publication needs operator inspection and cannot be guessed into authorization.

## 4. install_report

`install_report(&self, plan: OutputPlan) -> Result<GenerationReport>`

Install with a deterministic classified receipt.

```rust
let receipt = workspace.install_report(plan)?;
assert_eq!(receipt.generated, ["index.txt"]);
assert!(receipt.unchanged.is_empty());
assert_eq!(receipt.contract_version, 1);
```

| Parameter | Type | Meaning |
| --- | --- | --- |
| `plan` | `OutputPlan` | Same consumed plan as install. |

**Returns** Selected IDs, consumed auxiliary names, generated/unchanged/removed relative paths,
and writer contract version 1. It has the same errors and filesystem behavior as install.
The marker is excluded from path classifications. See [reports](reports.md).

## 5. recover

`recover(&self) -> Result<()>`

Recover recognized retained installation state. This independently compilable helper is
intended to run only after operator inspection; it is not called against the clean setup.

```rust
fn recover_owned_output(root: &std::path::Path) -> stackpress_idea_transformer::Result<()> {
    OutputWorkspace::new(root)?.recover()
}
```

**Returns** Unit after validating candidates, restoring/retaining a complete owned root, and
clearing recognized recovery state. Errors include lock conflicts, missing/unrecognized journal,
unmarked or edited retained trees, manual/special files, symlinks, missing candidates, and IO.
It never purges unknown manual data. Calling it on a healthy root with no journal is an error.

Recovery prefers a valid installed root; otherwise a complete backup; otherwise a complete
first-install stage. Recognized cleanup intent permits missing promised backup files while
requiring a valid installed root. A partial backup is never restored. A killed writer's lock
must be explicitly removed by an operator after establishing no writer remains; no PID-based
reclamation occurs. See [recover output](../guides/recovering-output.md).

## 6. Ownership and platform limits

The marker records relative paths, owners, last-installed SHA-256, and byte lengths. Older
entries may omit byte lengths but still require matching digests. Hashes detect cooperative
drift, not malicious marker forgery. Output roots, ancestors, marker, promised files, and
recovery state reject symlinks; managed text rejects nonregular files before opening.

All writers must cooperate with a single exclusive owner. Check/open/rename/delete races with
uncooperative external editors are outside the contract. Lock acquisition fails immediately;
ordinary return/unwind releases it, process death leaves it. Same-parent stage/backup renames
can leave a visibility gap. No crash-atomic, power-loss durability, network-filesystem, or
unverified platform guarantee is made. Native evidence is `aarch64-apple-darwin` only.
