# Verify session documentation and examples

Every Rust fence in the README/docs tree is classified and compile-checked as exact source in a disposable workspace outside the repository. Existing Rustdoc/compile-fail tests and the compiled finite SSR host remain separate evidence; Markdown compilation is not implementation coverage.

## Links, structure and claim anchors

Run `python3 crates/framework/framework-session/docs/check.py` from the checkout through the benchmark recorder. It checks one H1, heading orientation, tagged/classified fences, single blank-line separation, all local paths/heading anchors and the [claim map](claims.json). Every behavior section also links implementation, regression tests or a source oracle for manual review. There are no external web links to probe.

The map checks representative statements and source/test anchors for drift; it cannot prove arbitrary prose. Review exact defaults, mutation/error order, privacy boundaries and [the seven open questions](source-behavior.md#open-owner-questions) against their linked evidence. The checker includes negative controls for omitted example classification, invalid links/anchors and stale claims.

## Compile exact examples

Set an absolute effort CARGO_TARGET_DIR and invoke `docs/check.py --compile` through the recorder and bounded effort wrapper. It copies existing direct/plugin/facade/browser consumer manifests and byte-identical locks outside the repository, makes path dependencies absolute and puts each fence in a separate module. Examples cannot borrow imports from other fences. Every Cargo invocation is --locked --offline; root and repository consumer locks remain unchanged.

Native examples reuse the corresponding distinct `consumer-session-direct`, `consumer-session-plugin` and `consumer-session-facade` targets below the effort target to preserve dependency artifacts. Finite zero-argument examples execute: JWT, permissions, schema defaults, in-process identity, direct signout, hook lifecycle, template strings, real SQLite CRUD/close, CSV and facade identity. Functions accepting caller/Engine state compile without running. Browser fences compile for wasm32-unknown-unknown in both hydrate and CSR modes using the separate browser target; no browser/listener starts during that compile check.

Run `cargo check -p stackpress-framework-session --features leptos-ssr --example account_host --locked --offline` for the linked complete native SSR example. The existing [browser builder](../consumers/browser/build.py) compiles the linked browser entry. [Source Rustdoc](../src/lib.rs) is checked by workspace doctests and `cargo doc --workspace --no-deps` with RUSTDOCFLAGS=-D warnings and the released compatible feature set. These checks are distinct from tests of exact Markdown fences.

## Existing runtime evidence

The [claim map](claims.json) links current native, SQL, account, UI and composition tests. Source-derived fixtures are generated by finite read-only upstream loaders under [proofs](../proofs/); [source behavior](source-behavior.md) records provenance and mechanics limits. [Consumer graphs](../consumers/graphs.py) with --check and [consumer runner](../consumers/run.py) cover default/opt-in/disabled facade, constituents/composite and native/WASM feature isolation. [Browser matrix](../proofs/browser.cjs) covers all 16 pages, themes, translations, keyboard, phone and copy controls under hydrate and CSR with intercepted requests.

The docs-stage receipt records exact commands, counts and benchmark IDs. Its immutable-source audit distinguishes current docs compilation from the coordinator's accepted rounds runtime/coverage results. No coverage percentage is inferred from documentation or compilation.

## Resource and platform boundaries

The effort uses target/slice9a, sccache and bounded jobs, with a 24 GiB cap and 23.4 GiB headroom guard. Record the outer proof once; do not double-wrap its nested Cargo calls. Workspace nextest must exclude tcp_watchdog, owned by coordinator verification. No listener, live provider/backend, installed application or remote delivery acceptance is part of documentation checks. Keep locks unchanged and do not use renderer all-features.
