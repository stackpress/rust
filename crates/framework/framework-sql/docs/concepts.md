# Executors, projections and acknowledgements

`DataSession` borrows either an app-owned Engine or one exclusive Transaction. It captures no alternate pool and cannot be cloned or registered as a service. Limits come from the selected executor; a transaction keeps the copy frozen at begin. A single pooled statement is independent. Counts plus rows, eager includes and batches require one explicit transaction; SQLite's snapshot is the proved multi-statement contract.

Stored records, public records, eager views and default selections are distinct. `View0` through `View3` are finite owned types. Each edge is `Loaded::Unloaded` or `Loaded::Loaded(value)`, where optional `None` and an empty collection retain their usual meaning. Public projection is applied at every loaded node. `Selected` has a private payload and serializes the approved `@query` paths. With no source `@query`, detail falls back to the approved base row; an explicit selection with no approved paths produces an empty object. A selection never grants exposure. Detail resolves keys through the public query allowlist; a wholly private key is refused there, while trusted get_key remains available. A host exposing such a model can select get or implement its own authorized detail workflow.

Writes validate/prepare before effects, submit once, and decode the authoritative RETURNING row. Default providers/business validators run once per prepared instance. Timestamp refresh uses an explicit `ValueContext` clock; IDs and generated fields cannot be patched. Update is last writer wins, with no expected version. `InsertOutcome::AlreadyExists` means successful targeted no-change and has no fabricated existing row. Native unique upsert may return an existing primary identity different from the candidate's identity.

A submitted write or COMMIT failure conservatively yields `DataErrorKind::UnknownOutcome`, with its typed cause private. No portable known-unique category exists in the current adapter interface, so generated handlers do not guess a 409 from text. Cancelling an unacknowledged call is also uncertain; an autocommit effect may already be durable. A display refetch cannot prove rollback or authorize replay. Caller-owned transaction cancellation retains the adapter's rollback/retirement policy.

Public handler policy is app-owned and synchronous. It authorizes before decoding or IO and may supply owned private values/providers/clock. Direct stores are trusted domain calls and do not run that policy. Policies requiring transactional data access should live in an app-owned domain workflow using one session. Nested dispatch inherits neither a transaction nor authorization. HTTP/CLI mappings are explicitly supplied by the app.
