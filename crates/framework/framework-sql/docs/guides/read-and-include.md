# Read a page with bounded relations

Use generated native `Query`, `Filter` and `SortField` types for trusted domain queries. External handlers accept the frozen schema-owned `<Model>Query` and enforce its public allowlist. Unknown fields/operators/include segments and unsupported sort paths fail before query IO. Text `q` is case-sensitive literal containment; `%`, `_` and quotes stay binds. `Like` is a separate bound pattern operator with backslash escape. `Has`/`Hasnt` test scalar membership in a direct JSON-array column; no arbitrary JSON path or database regex is accepted.

`search` returns `Page<View3>` with base order and page limits applied independently of relations. `total` is an optional matched-base count before skip/take; zero stays zero. Default take is 20, maximum 100; skip is at most 100000. Sorts have explicit direction/null placement, then append every missing primary-key member as a stable tie breaker. SQLite datetime ordering/comparison normalizes canonical UTC precision in an audited expression without changing stored values or losing nanoseconds.

Pass a transaction session when requesting total or includes, or use `Models::search_atomic`. The loader groups/deduplicates keys and fetches one requested path level in bounded chunks across all its parents. It reserves active-predicate binds and validates SQL/bind/byte budgets against the exact executor before submitting each planned relation query. It never raises limits, retries a failed query or fetches a relation per parent.

`RelationLimits` can lower path/depth/row/byte/key/statement ceilings: 16 paths, depth 3, 10000 related rows/keys, 16 MiB logical output and 128 statements including base/count. Overflow errors rather than truncating a collection. Temporary materialized view caches have a separate bound of four times the logical byte ceiling. Explicit repeated relation cycles remain finite; unloaded, loaded empty and loaded optional absence remain distinct. Missing required targets and nonunique singular results are decode/integrity errors.

Ordinary active-model reads hide inactive rows, including related ordinary reads. Trusted maintenance methods take explicit `Visibility::{Inactive,All}`; public requests cannot select that policy. `remove`/`restore` are idempotent Boolean transitions with validation and timestamp refresh. Hard `delete` is a separate selected capability with RESTRICT foreign keys. Relations never imply nested writes or implicit join tables.
