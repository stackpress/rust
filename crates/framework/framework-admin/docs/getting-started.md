# Render generated roles

The included example imports the existing generated-workspace schema and selects schema, SQL, and UI functions in one app-owned tool. From the repository root, generate its marked output:

```sh
cargo run -p generated-admin-tool --locked -- emit generate
cargo run -p generated-admin-web --locked > /private/tmp/generated-admin.html
```

Open the HTML file to see Profile, Project, and Task list values, detail values, and native fields. The finite executable writes HTML to stdout and exits. The additional RoleProof section exercises nullable text, literal defaults, false, zero, and omitted sensitive/host fields.

For actual interaction, use the finite [browser proof](../../../../examples/generated-admin/README.md). The shared crate supplies the same component source for SSR, hydration, and CSR. Generation creates contracts, metadata, stores, and UI partitions; the frontend includes only contracts and UI modules.

Verify generated bytes without writing them:

```sh
cargo run -p generated-admin-tool --locked -- emit generate --check
```

A changed schema or plugin catalog makes check mode fail until regeneration. The tool has no dependency on its generated consumer, so an absent output root can be generated before the consumer compiles.

For M5 CRUD, follow the example README's `m5_build.py` and `m5_browser.py` instructions. They build the real generated SQLite host and both browser modes, then exercise compiled buffered HTTP routes through .invalid interception without a listener. The legacy no-argument HTML render above remains a finite role catalog.
